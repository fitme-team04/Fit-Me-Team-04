# 현재 실행 방식: 모델 파일 캐시 + 요청별 Blender

신체·의류 서버 모두 Blender를 상주시키지 않습니다. 시작 시 Blender 원본을 메모리에 올리는 호출을 제거했고, 작업 요청마다 `subprocess.run`으로 실행한 뒤 GLB 출력 또는 측정이 끝나면 종료합니다. 예전 `AVATAR_BLENDER_MODE=resident` 값이 남아 있어도 현재 API는 상주 경로를 호출하지 않습니다.

- **원본 파일:** VM 디스크에 보관합니다. 신체의 model-sync와 의류의 시작 모델 다운로드·크기·해시 검증은 유지합니다. 이미 정상적인 캐시가 있으면 다시 다운로드하지 않습니다.
- **신체:** SAM 표면 측정용 Blender와 최종 신체 생성용 Blender를 각 단계에서 실행·종료합니다. 최종 생성은 독립된 객체·메시·셰이프키 사본으로 작업하고 사본을 제거합니다. 원본 모델 파일은 수정하지 않습니다.
- **의류:** 요청마다 로컬 모델 파일을 읽어 상의 변형 또는 고정 하의 출력 후 종료합니다. 상의 뒷목 기준, 상의 measures 전용, 하의 고정 원형, 기존 기준점·핏 판정 정책은 유지합니다.
- **SAM 추론:** SAM 모델 자체의 기존 상주 설정은 유지합니다. 이번 변경은 Blender 프로세스에만 해당합니다.
- **오류·동시성:** 기존 422·429·503·504 처리와 단일 작업 제한을 유지합니다. 결과 임시 파일은 요청 종료 시 닫힙니다.

시작 시 모델 다운로드·검증을 한 번 한다는 것과 Blender 모델을 RAM에 계속 보관한다는 것은 다릅니다. 현재는 **파일 캐시만 유지**하며 Blender 프로세스와 그 메모리는 요청 종료 시 해제됩니다.

사용하지 않는 Blender 상주 모듈·수동 시험 도구는 제거했습니다. API는 요청별 프로세스 실행으로 고정되어 있습니다. 모델 파일·Blob 업로드 경로·manifest 해시는 바뀌지 않았으므로 다시 업로드할 필요는 없습니다. 코드 변경 반영에는 두 서버 이미지 재빌드·재배포가 필요하며 실제 VM 배포는 수행하지 않았습니다.
