# 사진 구도 검사와 실패 표시

카메라 촬영은 서버와 3D 상품 연결 확인을 기다립니다. 연결·로그인·상품 등록 확인이 실패하면 사진을 보내거나 예시 신체를 대신 표시하지 않습니다. 명시적인 `?loading=preview`만 예시 신체와 근사 옷을 사용합니다. 카메라의 전체 프레임을 표시하므로 촬영 전 가이드와 저장 사진의 범위가 일치합니다.

실제 사진 API는 한 사람을 검출한 뒤 `core/photo_visibility.py`로 원본 사진의 사람 영역과 머리·몸통·발·손목 투영 좌표를 검사합니다. 고정 A 자세로 바꾸기 전의 결과를 사용합니다. 잘림 또는 불충분한 근거는 `full_body_required`의 HTTP 422이며, 신체 GLB와 의류 생성으로 진행하지 않습니다. 여러 사람 또는 사람 미검출은 `single_person_required`입니다. 상주 GPU 프로세스는 입력 오류 후에도 재사용합니다.

통과 근거는 GLB scene extras `photo_validation`에 기록합니다. `/health`의 `photo_framing_check`는 `sam_projected_full_body_v1`, `source_revision`은 배포한 커밋입니다. SAM 투영점은 독립적인 2D 관측 신뢰도가 아니므로 물체에 가려진 부위나 모든 미관측 추정을 판별하는 기능은 아닙니다. 정상 전신과 실제 사진을 자른 회귀 입력으로 검증합니다.

웹은 알려진 사진 오류 코드만 재촬영 안내로 전달합니다. 신체 생성이 실패하면 의류 VM을 호출하지 않습니다. 신체는 성공했지만 의류 생성·다운로드·검증·정렬이 실패하면 신체만 표시하고 원인을 알립니다. 유효한 실패 의류 GLB가 있으면 마지막 실패 모습과 실패 상태를 그대로 표시합니다. 상품 실측 기반 핏 판정은 별도이며 수정하지 않습니다.

## 배포

전체 Dockerfile은 새 환경의 CUDA·SAM·Blender 의존성을 구축합니다. 소스만 변경한 기존 VM에는 `infra/deploy/Dockerfile.avatar-source`와 `infra/deploy/body-source-update.sh`로 검증된 기존 런타임 위에 커밋된 `src/`를 배치할 수 있습니다. 새 패키지가 필요한 변경에는 이 경로를 사용하지 않습니다.

`/opt/fitme-avatar/releases/<commit>/`에 해당 커밋의 소스·Dockerfile·SHA-256 manifest를 배치한 뒤 `bash body-source-update.sh <commit>`을 실행합니다. 스크립트는 manifest 검증, 네트워크 없는 이미지 빌드와 API import, 이전 이미지·소스 보존, avatar 단독 교체와 기동 확인을 수행합니다. 모델 동기화 서비스·환경 파일·읽기 전용 모델 마운트는 변경하지 않습니다. 상주 SAM이 새 검사를 읽도록 컨테이너를 재생성합니다.

검증은 정상 전신 2건, 기존 다중 인물 거절 1건, 머리·발·상반신·얼굴 잘림과 여백을 추가한 상반신·빈 화면 거절, 거절 후 정상 요청 복구를 포함합니다. 키 170cm·몸무게 65kg은 테스트 입력이며 사진 인물의 실제 치수라는 뜻이 아닙니다.
