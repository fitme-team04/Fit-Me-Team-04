# SAM 신체 기준 의류 크기 맞춤

`body_model_id`가 있는 의류 생성 요청은 상품·사이즈의 존재와 템플릿 종류만 DB에서 확인합니다. 상품 실측과 소매 별칭을 조회하거나 의류 변형 입력으로 사용하지 않습니다. 신체 없는 요청의 기존 상품 치수 생성은 유지합니다.

## 생성 과정

1. 등록 원형의 해시·바인딩·메시 품질을 검사합니다.
2. 실제 SAM GLB의 닫힌 몸통 단면·엉덩이 높이와 팔축에 수직인 독립 팔 단면으로 의류 사본을 변형합니다. 팔의 면적 중심 offset과 두께를 분리하며 별도 팔·손 윤곽은 몸통에서 제외합니다.
3. 상의는 signed clearance 9mm 미만 정점만 Blender Shrinkwrap OUTSIDE_SURFACE offset 10mm로 보정합니다. 몸통 프로파일의 20mm 여유는 유지하고, 팔 목표 윤곽에는 별도로 10mm를 적용합니다. 국소 Smooth와 Decimate 뒤에도 같은 상의 접촉 정책을 사용하며 하의는 기존 <16mm → offset 20mm를 유지합니다.
4. 2,500면을 넘는 의류는 Blender Decimate 0.2로 미세 삼각형을 정리합니다. UV·재질 데이터 보존 옵션을 사용하며 양방향 정점→표면 표본 오차가 6mm를 넘으면 실패 처리합니다. 이 표본 검사가 모든 표면의 최대 오차를 보장하지는 않습니다.
5. 새 SAM 맞춤 형태를 spring rest로 사용합니다. 중력 없는 Cloth + 신체 Collision 안정화를 최대 36프레임 수행하고, 12프레임부터 안정 조건이 충족되면 종료합니다. 낙하·중력 드레이핑을 재현하는 모드는 아닙니다.
6. 실제 전체 SAM과의 관통, 옷 자체 교차·퇴화, 새 rest 대비 늘어남 0.5%·줄어듦 2%, 안정성을 검사합니다. 실패해도 마지막 GLB와 사유를 저장합니다.

원본 SAM 자산과 원형 템플릿 파일은 수정하지 않습니다. 결과는 `fitting_mode=sam_body_cloth_collision`이며 `cloth_simulation.body_sizing.catalog_measurements_used=false`를 기록합니다. 상품 DB 실측을 재현한 측정 보고서는 만들지 않습니다. 실제 상품 사이즈 판정은 별도 DB 실측 비교를 사용하고, 화면은 SAM 신체 맞춤 3D임을 표시합니다.

## 팔 단면과 어깨 연결

`core.body_sections.arm_contour`는 실제 어깨→손목 축에 수직인 평면에서 닫힌 팔 윤곽 하나를 선택합니다. 원형 소매와 SAM 팔 각각 진행률 0.04~0.98의 32단면을 손목에서 어깨 방향으로 추적하고, 과대 반경 또는 직전 유효 면적의 0.35~2배 범위 밖인 단면을 제외합니다. 근위 진행률 0.35 미만에서 독립 단면을 잃으면 마지막 유효 중심·두께 프로파일을 이어 쓰며 유효 단면이 4개 미만이면 `sam_sizing_failed`로 저장합니다.

`core.arm_profiles.ellipse_section`은 단면의 다각형 면적 중심을 구해 축으로부터의 중심 offset과 실제 두께를 분리합니다. 한쪽에 정점이 더 촘촘해져도 같은 다각형의 면적 중심은 유지됩니다. 원형 소매를 단면 타원 좌표로 정규화한 뒤, 목표는 실제 SAM 윤곽의 convex hull 지지 직선을 10mm 평행 이동한 `offset_radial_profile`의 64각도 방사 표로 만듭니다. 중심이 축에서 벗어난 거리를 팔 반경에 더하거나 목표 전체를 큰 enclosing 타원으로 대체하는 기존 팽창 계산을 사용하지 않습니다.

몸통·소매는 원형 어깨 주변 12cm에 걸쳐 부드럽게 전환합니다. 소맷단 앵커에는 손목 방향 끝점뿐 아니라 목표 단면 중심 offset도 반영합니다. 원본 SAM 신체·원형 파일은 유지합니다.

`body_sizing.sleeves.L/R.method`는 `isolated_arm_offset_contour`입니다. `body_profile`·`source_profile`에서 유효/제외 단면 수와 진행률 범위·원래 단면 둘레 범위를, `sections`에서 중심 offset·진단용 enclosing 반경·`target_profile_girth_cm`를 확인합니다. 목표 프로파일의 64각 표본 다각형 둘레와 정확한 convex miter offset 다각형 둘레는 별도 값입니다. 예를 들어 각진 모서리를 각도 표본 사이의 chord가 가로지르면 표본 둘레가 더 작을 수 있습니다. 이 목표 둘레는 최종 저장된 소매의 직접 단면 실측과도 구분합니다.

팔 형태 회귀는 관통·자기 교차 0뿐 아니라 실제 저장 메시의 단면 중심·둘레·면적, 부위별 신체 여유와 어깨 전환 경계를 함께 비교합니다. 프로파일 생성 → 접촉 보정 → Decimate → Cloth 이후를 같은 단면으로 비교해 팽창이 발생한 단계를 확인합니다.

운영 경로의 `_validate_sleeves`는 크기 조정·접촉 보정·Decimate와 최종 국소 접힘 완화가 끝난 뒤 Cloth 전에 실제 의류의 진행률 0.4/0.55/0.75/0.9 단면을 검사합니다. 목표 중심과 10mm 넘게 다르거나 목표 프로파일 둘레보다 20mm 넘게 크거나 30mm 넘게 작으면 실패합니다. 실제 둘레·목표 둘레·중심 차이는 `body_sizing.sleeve_fit_validation`에 남깁니다. 이 검사는 크기 맞춤 단계가 다시 과대·과소 변형되는 것을 막으며 이후 spring rest 대비 늘어남 0.5% 검사와 별개입니다. 최종 Cloth 이후의 관통·자기 교차·새 rest 대비 변형 검사는 그대로 유지합니다.

## 서버에서 확인할 항목

인증된 기존 신체의 `body_model_id`를 `/api/garments` 요청에 전달합니다. 반환된 GLB의 `fitme_garment.fitting_mode`, `cloth_simulation.body_sizing`, `status`, `failure_reasons`, `frames`, `initial_intersection_samples`, `final_intersection_count`를 확인합니다. 서버 로그의 `sam_sizing_start`, `sam_sizing_complete`, `self_collision_resolution`, `cloth_frame`, `final_export_complete`가 실제 호출 경로입니다.

팔·소매 검증에는 `body_sizing.sleeves`와 최종 GLB의 동일 팔 평면 단면 실측을 함께 확인합니다. 현재 상의 접촉 설정은 `contact_guard_trigger_m=0.009`, `contact_guard_offset_m=0.010`, `sleeve_clearance_m=0.010`이며 `clearance_m=0.020`의 scope는 몸통 프로파일입니다.

웹은 반환된 `body_model_id`가 현재 신체와 일치하는지도 검사합니다. 이전 신체에 대한 늦은 응답은 새 신체 화면에 적용하지 않습니다.
