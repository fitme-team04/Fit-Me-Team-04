# 하의 상품 입력: 네 치수와 고정 비율

현재 하의 API는 다음 네 값만 요구합니다. 단위는 cm입니다.

| 상품 입력 | 의미 | 최종 원형의 기준 설정 |
| --- | --- | ---: |
| `waist_width` | 허리단면 | 42 |
| `hip_width` | 엉덩이단면 | 52 |
| `thigh_width` | 허벅지단면 | 32 |
| `inseam` | 안쪽 기장 | 72 |

`front_rise`, `knee_width`, `hem_width`는 상품 DB에서 받지 않으며, 들어와도 생성 요청에서 제외합니다. 내부 케이지를 구성할 때 등록 원형의 비율을 적용합니다.

| 내부 형상 | 최종 원형에서 유지하는 관계 |
| --- | --- |
| 앞밑위 | 엉덩이단면 × (원형 앞밑위 30 ÷ 원형 엉덩이단면 52) |
| 무릎단면 | 허벅지단면 × (원형 무릎단면 26 ÷ 원형 허벅지단면 32) |
| 밑단단면 | 허벅지단면 × (원형 밑단단면 25 ÷ 원형 허벅지단면 32) |

예를 들어 엉덩이·허벅지가 각각 10% 커지면 앞밑위·무릎·밑단도 각 연결 부위에 맞춰 10% 커집니다. 안쪽 기장은 별도 입력으로 다리 길이를 조절합니다. 허리 부착 기준점은 고정합니다. 신체 교차 보정·교차에 의한 출력 차단은 하지 않습니다.

비율의 기준은 각 템플릿 NPZ에 저장한 등록 당시 값입니다. 기존 NPZ의 일곱 값은 **상품에 요구하는 실측이 아니라 내부 원형 비율 자료**로 유지하므로 재바인딩 없이 기존 형상을 보존합니다. 새로 등록할 때도 외부 설정 네 개와 내부 케이지 기준을 구분해 저장합니다. 완성 메시의 실제 단면 실측을 정확하게 보장하는 기능은 아닙니다.

## 데이터 연결

3D API는 여전히 `garment.garments → garment.sizes → garment.measures`의 `basis='garment'` 값을 읽습니다. 이번 변경이 `garment.size_*` 브랜드별 테이블 조회를 자동 추가한 것은 아닙니다. 브랜드 테이블의 둘레 값을 사용할 때는 허리·엉덩이·허벅지 둘레를 각각 2로 나눠 위 필드에 연결해야 합니다. 이미 단면인 값은 다시 나누지 않습니다. 안쪽 기장은 그대로 사용합니다.

필수 네 값 자체가 없거나 비정상이면 422입니다. 앞밑위·무릎·밑단이 없다는 이유로 거절하지 않습니다. `/fit` 판정 API는 기존처럼 허리·엉덩이만 읽으며 이번 변경의 영향이 없습니다.

## 확인 결과와 배포

- 네 입력 각각 ±5%·±10%, 동시 ±5%·±10%, 기본값 총 21개 변형에서 유한 정점·단일 연결·개구부 세 개·고정 허리 기준점·파생 비율을 확인했습니다.
- 기본값 입력은 이전 최종 바지의 정점을 유지했습니다.
- 기본·동시 +5%를 실제 worker로 GLB 출력했고, 기본 GLB는 재입력하여 기준 신체와 교차 0건을 확인했습니다. 모든 변경 치수에서 무교차를 보장하는 검사는 아닙니다.
- API·비율 계약 테스트 4개와 `/fit` 회귀 테스트 5개가 통과했습니다.

최종 통합 폴더의 `pants/garment-spec.json`은 네 입력으로 갱신했습니다. 모델 ID `black_midrise_straight_v1`은 유지하며 revision은 `1.1`입니다. 갱신 코드와 통합 `models/registry.json`을 함께 배포해야 합니다. `.blend`와 `.npz`는 기존 원형을 유지합니다. VM·Azure DB·Blob에는 아직 적용하지 않았습니다. 현재 검사 결과는 `pants/four-input-validation/`, 예전 `pants/size-checks/`는 이전 일곱 입력 계약의 기록입니다.
