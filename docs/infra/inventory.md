# 인프라 담당이 손댄 요소 전체 목록 (Fit Me 인프라·DevOps)

> 인프라·DevOps 담당이 이번 프로젝트에서 손댄 것 모음 (11/20 기준, `infra-checklist.md`·`daily/`·`work-log.md`에서 모음)
> **인프라 담당이 했나** 칸: 인프라 담당이 직접 한 건 "했음", 팀원이 한 건 "안 했음"으로 적고, 섞인 건 어디까지 했는지 적었어요.
> 공개용이라 IP·주소·키·계정 이름·이메일은 뺐어요. 리소스 이름은 그대로 뒀어요(이름만으로는 접속 못 함).

## 3. 권한 (IAM) — 필요한 범위로만

| 누구(무엇) | 역할 | 범위 | 이유 |
|---|---|---|---|
| GitHub Actions용 계정 | Contributor | 리소스 그룹 | 배포·Terraform만. **Owner 금지** → 파이프라인은 권한 주기 못 함 |
| 웹 VM · 신체 VM · 의류 VM (관리 ID) | AcrPull | Container Registry | 이미지 받기만 |
| 신체 VM | Storage Blob Data Contributor | `body-glb` 컨테이너만 | 3D 몸 파일 쓰기 |
| 의류 VM | Storage Blob Data Contributor | `garment-glb` 컨테이너만 | 3D 옷 파일 쓰기 |
| 신체 VM · 의류 VM | Storage Blob Delegator | Storage 계정 | 브라우저용 임시 읽기 링크(SAS) 서명만, 데이터 권한 없음 |
| 신체 VM | Storage Blob Data Reader | `avatar-models` 컨테이너만 | AI 모델 파일 읽기 |
| 의류 VM | Storage Blob Data Reader | `garment-models` 컨테이너만 | 옷 원본 파일 읽기 |
| 의류 VM | SQL DB 사용자(관리 ID) + 읽기(SELECT) | `garment`·`ref` 스키마 | 비밀번호 없이 DB 읽기만 |
| 인프라 담당 | Key Vault Secrets Officer | Key Vault 하나 | 비밀값 넣기 (RBAC라 Owner여도 따로 필요) |
| 팀원 | Entra 그룹 → SQL 관리자 | SQL 서버 | 팀원 각자 자기 계정으로 DB 접속 |
| 의류 VM | Storage Blob Data Reader | `body-glb` 컨테이너만 | 옷을 몸에 맞춰 입히려고 신체 3D 파일 읽기 (11/17 추가) |

> 계정·RG 전체가 아니라 **컨테이너·리소스 단위**로 좁힌 게 핵심 (예: VM이 ML 데이터를 지울 수 없게)

| 워크플로 | 흐름 | 결과 |

## 12. 왜 썼고, 무엇을 얻고, 무엇을 배웠나

> 위 1~11번에 나온 요소를 주제별로 묶었어요. 효과에는 기록에 남은 숫자를 넣었어요.

### 서버·네트워크

| 요소 | 왜 썼나 | 효과 | 배운 점 |
|---|---|---|---|
| VM + Docker (App Service 대신) | 프론트·3D 서버가 Redis·MySQL·Blender·GPU처럼 각자 필요한 게 달라서 서버 안을 직접 다룰 수 있어야 했음 | 서버 3대를 같은 방식(Compose)으로 올리고, 컨테이너만 바꿔 배포·되돌리기 가능 | 관리형 서비스는 편하지만 GPU·특수 프로그램이 들어가면 VM이 더 유연함. 대신 업데이트·보안은 내 몫이 됨 |
| GPU VM T4 1대 (NC4as_T4_v3) | 사진에서 3D 몸을 만드는 SAM 3D Body가 GPU 필요 | 직접 시험해 장당 약 6초, 메모리 최대 약 11GB/16GB 확인 → 더 비싼 GPU 없이 T4 1대로 충분 | 사양은 추측하지 말고 작게 먼저 돌려 재 보고 고르기. 큰 VM으로 바꿔도 속도가 안 빨라지는 경우가 있음 |
| VNet 1개 + 서브넷 3개 + NSG | 바깥에 열 곳(웹)과 숨길 곳(3D·DB)을 나누기 위해 | 바깥에 열린 건 웹 443(·80)뿐, 3D 서버는 웹에서만, DB 포트는 내부에서만 | 서브넷을 역할별로 나누면 규칙이 단순해지고 그림으로 설명하기도 쉬움. 기본 규칙(VNet 안끼리 허용)을 막는 마지막 규칙이 필요함 |
| 공인 IP + NSG (NAT Gateway 대신) | 새 서브넷은 기본 인터넷 출구가 없어 VM이 패키지를 못 받을 수 있었음 | NAT Gateway 월 약 4~5만 원을 쓰지 않음 | 같은 문제라도 기간·예산에 맞는 해결을 고르기. 들어오는 건 NSG로 막으면 공인 IP도 안전하게 쓸 수 있음 |
| nginx + Let's Encrypt + 사이트 로그인 | 웹 화면 기능이 https에서만 동작하고, 개발 중 사이트를 아무나 보면 안 돼서 | 무료 인증서 자동 갱신, 3D 서버는 nginx 뒤에 숨김 | https는 보안만이 아니라 브라우저 기능을 쓰기 위한 조건이기도 함 |
| 무료 Azure 주소(cloudapp) | 도메인 구매·결제자 결정 없이 바로 https 주소가 필요 | 비용 0원, 당일 https 완료 | 발표용이면 무료 주소로 충분. 도메인은 나중에 붙여도 됨 |
